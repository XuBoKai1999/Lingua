## 0. 本輪最重要的結論（截至本次討論）

Lingua 的教材仍採四層架構，但**四層不代表四次必要的 AI 呼叫**：

1. **教材總規範**：由 GUI／人工設定、模板或外部討論後建立，結果是 `course.json`。
2. **具體 Units 規劃**：由既有課綱模板、GUI 人工編輯，或「與 AI 討論 → 人工定稿 → AI 整理」取得，結果是 `units.json`。**AI 可選，但不是建立 Units 的必需步驟。**
3. **每個 Unit 的詞彙表**：此處開始由 AI 生成，依有效上層規範與指定 Unit 產生詞彙及慣用表達。
4. **每個 Unit 的學習材料**：由 AI 根據詞彙表與必要上下文生成文章、對話、情境故事等；再由程式完成 TTS。

核心關係：

```text
[人工／模板] course.json ───────────────┐
                 ↓                     │
[模板／人工／選擇性 AI 討論] units.json ─┤
                 ↓                     │  組合相關規範
       [AI] 某個 Unit 的詞彙表  <───────┤
                 ↓                     │
       [AI] 該 Unit 的學習材料 <────────┘
                 ↓
              [程式] TTS
```

在第二步，AI 的任務主要是**協助開放式討論與整理已確認課綱**，而非擁有自行決定最終 Units 的權力。兩份上游 JSON 是明確可人工檢查、修改及保存的資料。

## 1. 從完整教材到按需延伸的教材

### 1.1 早期擬議的七階段完整課程（歷史方案）

曾考慮一套適用於任何語言、總計約 **280 Units** 的通用課程：

| 階段 | 早期名稱 | 估計 Units |
| --- | --- | ---: |
| 0 | 緊急生存 | 16 |
| 1 | 短期旅居 | 28 |
| 2 | 獨立生活 | 44 |
| 3 | 社會融入 | 40 |
| 4 | 大學與職業 | 44 |
| 5 | 公共知識與一般閱讀 | 44 |
| 6 | 高階思想、文學與創作 | 64 |

此表是**早期探索，不是目前必須實作的七階段制**。Unit 數字原本只是估計；尤其階段 5 的自然科學、文學等範圍可無限擴張，難以合理預先切成固定數量的 Units。

### 1.2 收斂為「落地生根」通用模板

隨後決定，目前**唯一優先考慮的通用課綱模板**是「落地生根」，只保留階段 0～3：

| 階段 | 主要能力目標 | 原估 Units |
| --- | --- | ---: |
| 0｜緊急生存 | 求助、緊急醫療、基本移動、飲食、住宿、安全 | 16 |
| 1｜短期旅居 | 交通、旅遊、消費、住宿、處理行程變化 | 28 |
| 2｜獨立生活 | 租屋、醫療、金融、行政、求職、日常維生 | 44 |
| 3｜社會融入 | 文化、社交、溝通、協商、權益、公共事務 | 40 |
| **合計** | | **約 128** |

- **階段 0～3 的方向被視為必要**，其中前 0～1 直接對應短期出國需求。
- 原階段 4「大學與職業」可跳過，不納入目前通用模板；大學生活是否應獨立成教材亦有疑慮。
- 原階段 5、6 不再預先硬列進這個模板。哲學、心理學、科學、宗教、小說、論文寫作、考試等，可將來依需求另行規劃。
- **目前不要預先建立其他課綱模板**；「如無必要，勿增實體」。
- 討論中已將落地生根視為**預先給定 Units 的模板**，使用者選擇它時應可直接載入既有規劃，不必重新呼叫 AI。**但截至此紀錄，完整約 128 筆 Units 尚未逐筆形成正式 JSON；上述數量也不應視為 schema 驗收的固定值。** 既有示例與主題群不等於完整逐筆課綱。

### 1.3 重要區分：模板、教材實例、生成進度、學習進度

- **模板**：可重複使用的課程結構與能力目標，不等於已生成的完整內容。
- **教材實例**：例如一份英文「落地生根」教材，可在建立時從模板複製／修改 Units。
- **生成進度**：已經產生哪些 Units 的詞彙及材料；與模板覆蓋範圍不同。
- **學習進度**：使用者實際掌握多少；與生成多少不同。

教材**必須可漸進式生成**。例如先建立階段 0～1 的課綱，先生成幾個當下需要的 Units；之後可增加階段 2～3、或視需要新增／修改 Unit，而不應把舊材料全部重做。模板不應成為無法脫離、會反覆覆寫個別教材的外部約束。

當前實際優先順序：**先英文，再日文**，不是同步學三四種語言；現階段目標是出國／短期旅居所需的前 0～1 階段。未來仍可擴充更多語言。

## 2. 通用模板只規範能力，不固定跨語言的逐字內容

相同的「點餐」「看醫生」「搭車」目標，因目標語言、國家、地區與生活制度而有不同的詞彙和情境。

討論所得做法不是先製作每個國家的獨立課綱，而是：

1. `course.json` 能承載目標語言、目標國家／地區，以及長期有效的額外要求。
2. 生成 Prompt **預設要求考慮當地風土民情**、常見口語、交通、飲食、禮節、行政與醫療制度等；尤其適用於落地生根階段 0～3。
3. 生成 P3/P4 時注入目標 Unit 及相關上層規範；不得簡單地把其他國家的情境直譯。
4. 未指定地區時不應無依據假設某個特定國家。語言（例如英文、阿拉伯文）與地區／變體屬不同概念。
5. 使用者在生成 Prompt 時應有**自由補充需求**欄位，例如偏好獨自旅行、特定交通方式或特殊使用情境。

不同需求可分成**持久需求**（寫回教材／Unit JSON、會影響後續生成）及**單次需求**（只適用本次 Prompt、不修改來源 JSON）。不必為每個可能偏好新增專屬欄位。

## 3. 兩份上游 JSON：目前討論的最小結構

以下只是**schema 草案與欄位示例**，目前未正式定稿。關鍵是資料由人可直接編輯，AI 生成時按需要讀取，而非依賴整段討論文字。

### 3.1 `course.json`：教材總規範

```json
{
  "name": "English - 落地生根",
  "language": "English",
  "region": null,
  "template": "落地生根",
  "default_level": null,
  "requirements": "重視實際溝通與目標地區的風土民情，不安排獨立文法課程。"
}
```

討論中的欄位意義：

- `name`：教材名稱。
- `language`：目標語言。
- `region`：目標國家／地區；允許未指定。
- `template`：起始課綱模板；不代表教材永久被模板鎖定。
- `default_level`：教材層級的預設程度（可空），適合考試等偏向統一難度的情境。
- `requirements`：可自由編寫、往下層 Prompt 繼承的教材總需求。

**程度優先由每個 Unit 自行決定**；未指定時才繼承 `default_level`。階段與難度並不必然一一對應；同一「醫療」主題可以有不同深度。

### 3.2 `units.json`：課綱

```json
{
  "units": [
    {
      "id": "S0-U01",
      "stage": 0,
      "title": "緊急求助",
      "topic": "報警、呼救、尋求協助",
      "description": "能在危險或其他緊急情況中說明處境並請求協助。",
      "level": null,
      "requirements": ""
    }
  ]
}
```

- `id`：穩定且唯一，修改標題時不應任意更改。
- `stage`：階段式模板使用；一般課程可為 `null`。
- `title`：GUI 顯示的名稱。
- `topic`：該 Unit 的主題範圍。
- `description`：真正要能完成的任務／學習目標，避免只憑含糊標題生成詞彙。
- `level`：個別 Unit 難度，`null` 表示採全教材預設值或後續待定。
- `requirements`：Unit 專屬的持久要求。

範例只用來展示格式，**不代表它已是完整落地生根清單**。未來應由 GUI 檢查／修改／重排 Units，並驗證 JSON。

## 4. Units 的三種建立途徑

Step 2 的**最終交付物永遠是相同格式的 `units.json`**。建立途徑可以是：

1. **套用既有課綱 JSON 模板**：如「落地生根」，可選擇建立哪些階段、再自行修改。
2. **完全人工編輯**：在 GUI 新增、刪除、修改、重排 Unit。
3. **AI 協助開放式討論**：程式產生起始 Prompt（帶入 `course.json` 及補充要求）；使用者在 AI 對話中不斷調整規劃，定稿後以另一份固定 Prompt 將已確認的設計整理為 `units.json`，再匯入與驗證。

第三種途徑特別適合**多益（TOEIC）導向、學術英語或特殊目的教材**：先在 `course.json` 定義考試類型、用途與要求，再與 AI 討論應按題型、情境或其他方法切 Units。此討論不應被 GUI 強制拆成有限輪數。

**兩個可內建的 Prompt 角色：**

- **P2-A（規劃討論）**：把 `course.json`、既有 Units（若有）、本次補充需求與固定討論規則結合；請 AI 提出課綱建議、重要性、難度、缺漏，但在人工宣布定稿前**不要輸出最終 JSON**。
- **P2-B（定稿清洗）**：把**已確認的課綱方案**轉成合規 `units.json`。不得混入已被否決的舊方案；若是擴充既有教材，不任意改動舊 Unit ID，也不擅增未討論的主題。匯入後仍可人工核對及修改。

此二 Prompt 都屬於**可選輔助**。它們不推翻「前兩步只要求 JSON，後兩步才必須進入 AI 內容生成」的主軸。

## 5. P3/P4 的 Prompt 裝配邏輯

### P3：指定 Unit 的單字表

建議必要上下文：

- 有效的教材語言、地區、用途、程度、教材持久需求。
- 目前 Unit 的 `id/title/topic/description/level/requirements`。
- 本次生成的自由補充要求。

按需可加入：過往單字表、其他 Units 的概覽、個人學習進度等；不必無條件塞入整份 128 Units JSON。

詞彙核心是實用的**單字、片語、固定搭配與慣用表達**，不是純粹孤立的單字列表。不安排獨立文法教學，但文句要自然且符合用途。詞數、選詞頻率、複習與輸出 schema 尚需實驗。

### P4：指定 Unit 的材料

建議必要上下文：

- P3 所用的相關教材／Unit 規範。
- 此 Unit **已確認的單字表**。
- 材料種類與本次額外需求。

AI 可能生成對話、情境短文、故事、實戰角色扮演任務等，一個 Unit 可包含多種材料；不應為了覆蓋單字而寫出不自然的句子。

初期應提供聆聽／文字閱讀能力與 TTS；口說練習可先透過引導 Prompt 進入 GPT 對話，未來再考慮 API。**每個 Unit 的聽說是產品方向，但精確的第一版功能範圍尚未定案。** 寫作與進階閱讀理解互動可留待後期。單字表和材料的最終 JSON schema、音檔切分與同步方式目前都未定案。

TTS 應由程式針對生成的目標語言文字產生，而不是要求 LLM 假裝輸出音檔。既有 [Ultimate English Learner](https://github.com/XuBoKai1999/Ultimate_English_Learner) 可以作為閱讀、TTS、手動 Prompt 工作流的參考，不需照抄。

### 裝配原則

```text
最終 Prompt
  = 固定任務模板（P2-A / P2-B / P3 / P4）
  + 當前作業必須的 course / unit / vocabulary 資料
  + 可選的背景脈絡
  + 使用者本次補充要求
  + 對應輸出規格
```

- **不是所有上游資訊都必須無條件完整灌入**：確保有效規範傳遞，同時控制冗餘。
- 規範具有作用範圍：教材持久需求可影響全教材；Unit 專屬需求只影響其分支；本次臨時需求只用於當次生成。
- 程式負責確定性的驗證與存檔（JSON 合法性、Unit ID 唯一、材料引用已存在詞彙等）；不需為這些檢查另呼叫 AI。
- AI 生成內容先人工審查，是否可局部重新生成、如何保留先前版本，有待設計。

## 6. GUI 的初步使用流程

產品首頁仍以簡單為主：

```text
Lingua
├── 進入教材
└── 創建新教材
    ├── Step 1：編輯教材總規範 -> course.json
    ├── Step 2：決定 Units -> units.json
    │   ├── 載入固定課綱模板
    │   ├── GUI 人工增刪／修改
    │   └── AI 討論 Prompt -> 定稿清洗 Prompt -> 匯入
    ├── Step 3：選定 Unit -> AI 生成詞彙表
    └── Step 4：AI 生成材料 -> 程式生成 TTS
```

- 創建教材並不要求立即把所有 Units 的詞彙、材料與音檔生成完。
- 可保留完整課綱但只逐一生成當下要學的 Units。
- 已有教材可逐步增補 Units 或擴充階段，尤其從落地生根階段 1 延伸至 2、3。
- GUI 不必整合完整聊天系統：提供可複製的起始討論／清洗 Prompt 與 JSON 匯入介面即可。
- 最初不建立額外語言管理層，亦不預先建立大量抽象類別。

## 7. 與先前提案的差異（留存歷史）

| 議題 | 曾提出的想法 | 本輪較新方向 |
| --- | --- | --- |
| 上游規劃 | P1 AI 生成教材總規範、P2 AI 直接規劃 Units | `course.json`、`units.json` 是最終結構；AI 僅可選擇性協助討論與清洗 |
| 通用課程 | 七階段、約 280 Units | **落地生根**只含 0～3，原估約 128 Units |
| 專業／學術擴充 | 固定大學、科學、哲學、文學等階段 | 暫不放入落地生根，待需要時專門討論、生成不同課綱 |

## 8. 尚未定案，請勿當成實作需求

1. **落地生根完整 Units 清單**：主題方向與範圍已討論，但需另行逐筆確認／輸出 `units.json`；16/28/44/40 為初估。
2. **正式 JSON schema**：此檔的欄位為草案，尤其 `stage`、難度值、地區／語言變體、模板追溯資訊、設定優先權尚可調整。
3. **新增階段／Unit 的衝突處理**：增補模板時如何避免重複 ID、如何處理人工改動；目前只確認不得無故覆寫舊內容。
4. **P2-A／P2-B 的最終文案**及在 GUI 中如何傳遞經人工確認的討論結果。
5. **P3 詞彙選取與輸出規格**：單字量、固定搭配、音標／讀音、詞性、例句、重複率、跨 Unit 複習。
6. **P4 材料生成與輸出規格**：材料類型、長度、覆蓋率、翻譯、朗讀切分、角色 TTS。
7. **口說／閱讀／寫作的第一版介面**與 GPT 對話 Prompt 的實際範圍。
8. **模板與教材實例的儲存路徑、版本紀錄、遷移及狀態追蹤**。
9. **不同語言的教材程度與文化差異**應如何描述，避免固定課綱強迫所有語言逐字一致。

## 9. 本紀錄對接下來開發的意義

- **先定義兩份上游 JSON 以及課綱模板的最小可用格式，再精煉 P2-A／P2-B、P3／P4 Prompt**。
- 優先以**英文落地生根階段 0～1**作實際測試，之後再做日文；不一次創建完整的高階學術教材。
- 目前沒有正式核准的程式模組分層、完整資料夾樹或開發施工順序；本檔不授權直接替討論中的方案建立一堆檔案。
- **如無必要，勿增實體**：本檔只是保留設計演進，後續重大修訂請新增歷史決議，而非將早期想法悄悄刪除。
