# 粗決議 04：落地生根課綱 v0.2 與對話式教材構想

> **日期**：2026-11-06  
> **性質**：課綱 v0.2 已獲初步認可；教材活動設計則只是使用者提出的**待討論構想**，不可當成已定稿的 P3／P4 規格。  
> **前序紀錄**：[粗決議 01](001_教材架構與生成流程_粗決議.md) · [粗決議 02](002_落地生根模板與Prompt工作流_討論紀錄.md) · [粗決議 03](003_教材與Units_JSON初版設計決議.md)

## 1. 本次已更新的課綱

檔案：
- [落地生根.json](../templates/units/落地生根.json)：主要資料。
- [落地生根.md](../templates/units/落地生根.md)：人工檢閱表格，應與 JSON 同步。

沿用四階段和 128 個 Unit ID，但重新安排主題：

| 階段 | v0.2 名稱 | Units | 方向 |
| --- | --- | ---: | --- |
| 0 | 基礎生存與溝通 | 16 | 基本問候、自我介紹與生存、緊急需求並行 |
| 1 | 旅行與日常交流 | 28 | 20 個旅行實務 + 8 個旅行社交 Units |
| 2 | 獨立生活與建立關係 | 44 | 更早安排日常交友，保留租屋、醫療、金融、求職等需求 |
| 3 | 社會融入與深入交流 | 40 | 深入對話、群體社交、衝突協商、社區與公共生活 |

### 本次修正理由

舊版大幅聚焦交通、付款、退換貨及行政等**辦事式語言**，階段 1 幾乎沒有「在旅行時和當地人簡單聊天」的練習；使用者明確指出這種設計有些「打高空」，與個人當前出國需求不符。

v0.2 因此將問候與基本介紹放在階段 0，將開啟話題、自我介紹、天氣與眼前事物、興趣、美食文化、旅行經驗、接話追問、告別／保持聯絡放在階段 1，後續階段才深化友誼、觀點表達與社會參與。

**注意**：v0.2 是目前可用來繼續設計的課綱，並非經過教學試驗驗證的完成版；仍可進一步整併或修改 Units。階段 0–3 的目標不同於固定 CEFR 級別，Unit 程度沿用既有 `level` 繼承規則。

## 2. 新提出的想法：以前期對話式教材為主（未定稿）

使用者提出：**至少在目前優先開發的旅行／生活早期階段，教材應以對話式為主**。

概念如下：

- **同一 Unit 可有數段短對話**，而非只有一篇長文章；每段聚焦具體情境與詞彙用途。
- 學習者可以**看文字、聽音檔、跟讀或照唸**。具體播放介面、逐句切分與跟讀評估方式尚未決定。
- **寫作可能也是活動之一**，但尚未確定內容、形式、應位於哪個階段或如何評分；未來可以參考典型外語教材／參考書的練習設計。
- 需要**獨立的互動環節**：傳統教材中與老師／同學的對練，在 Lingua 中可使用 GPT 扮演對話者與練習夥伴。
- 可能需要一種**局部／情境專用 Prompt**，在後期生成教材時一併產生或注入，讓學習者能複製到 ChatGPT 並開啟對話式互動。這與 Step 2 的「討論生成 Units」Prompt 用途不同。

### 暫定工作流示意（僅為討論方向）

```text
course.json + unit.json
       ↓
      P3：詞彙
       ↓
      P4：教材生成
       ├── 幾段短對話（可讀／可聽／可跟讀）
       ├── （選擇性）其他閱讀或寫作活動
       └── （選擇性）此 Unit 的 GPT 互動 Prompt／角色扮演指示
              ↓
       使用者複製到 GPT，與 AI 對話練習
```

上圖**不構成對新檔案、新程式模組或 JSON 欄位的要求**；只是記下可供後續 P3／P4 設計討論的交互關係。

## 3. 下一輪該討論而非現在直接實作的問題

1. 一個 Unit 的短對話應如何設計，是否需要多個不同難度／場合？可不可以由同一批詞彙產生？
2. 聽、看、跟讀應如何安排：先聽、後看文字，還是可自由選擇？是否有必要錄音比對？
3. 「寫」究竟指抄寫、填空、短句造句、情境回覆，或較自由的寫作？不同階段是否不同？
4. GPT 互動應在教材生成時**生成專屬 Prompt**、還是使用固定通用 Prompt 加上 Unit 資料？優先比較兩者的簡潔性與可維護性。
5. GPT 對話如何設定角色、目標、難度、糾錯時機及結束後回饋，避免只是由 AI 唸完預寫台詞。
6. 是否需要先查核典型教材（對話、替換練習、角色扮演、聽寫等）的常見教學活動，再定 P4？
7. 哪些是初版必要功能、哪些等到 API 或進階互動開發時再處理？

## 4. 設計紀律

- **如無必要，勿增實體**。先驗證最小教材生成與學習工作流；不要預建大型練習框架。
- 保持 `course.json`、`units.json` 作為教材總規範和課綱，**不直接混入學習活動狀態**。
- 本次除了更新已存在的兩份落地生根課綱檔，只新增此份歷史紀錄，不創建新的練習模組或 Prompt。
