## Must fix

1. **Primary controls are clipped at the supported 900×600 / 200% zoom setting** (`src/lingua/ui.py:360`, `src/lingua/ui.py:394`, `tests/test_ui.py:280`)
   - **What this is:** The workspace puts both header actions in one horizontal row and all four Unit actions in another horizontal row inside the narrow splitter pane.
   - **Problem:** In an offscreen 900×600 window at 200% zoom, the planning button was 134 px wide for a 254 px size hint, the edit button was 80 px for a 110 px size hint, and the four Unit buttons were only 20 px high for 32 px size hints. The existing 200% test only checks that the lesson-preview viewport has a positive size, so it passes while these primary labels and controls are compressed.
   - **Fix:** Use a responsive arrangement for these two action groups (for example, a vertical header action column and a 2×2 Unit action grid), then assert at 900×600 / 200% that each primary button meets its size hint and remains reachable.
   - **If we skip it:** The documented maximum zoom makes important edit, planning, add, delete, and ordering controls hard to read or operate on the minimum supported window.

2. **Editing a course name leaves its storage directory under the old name** (`src/lingua/storage.py:161`, `src/lingua/storage.py:202`, `src/lingua/ui.py:67`, `src/lingua/ui.py:694`)
   - **What this is:** Creation derives the directory from `course["name"]`, but Edit Course allows changing that field and `save_course()` only rewrites `course.json`.
   - **Problem:** Reproduced by creating `A`, editing its stored name to `B`, then creating `B`: the library contains `[('A', 'B'), ('B', 'B')]`. Creating a new visible `A` then fails because the hidden old `A` directory is still reserved.
   - **Fix:** When the name changes, validate the new safe sibling path, reject an existing target, rename the course directory, and update the workspace/navigation path only after the rename succeeds. Add a test for rename, collision cancellation, and reopen; if course names are intentionally immutable, make the field read-only instead.
   - **If we skip it:** Users can see duplicate course names and be blocked from creating a name that appears unused; later file operations continue to identify the course by stale metadata.
